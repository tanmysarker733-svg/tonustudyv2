NON-NEGOTIABLE N+1 RULE
1. Find the highest hsc-study-os__NNN_.html in the Version 2 mirror.
2. Copy it to hsc-study-os__NNN+1_.html. Never overwrite the prior number.
3. Make all feature/style/script edits in the new numbered copy.
4. Validate that new copy.
5. Copy that validated file into this repository as index.html.
6. Mirror the new numbered copy and index.html back to the Version 2 folder.

The numbered snapshots are local preservation history. Do not add every numbered
snapshot to GitHub unless the user explicitly asks. Normally GitHub receives only
index.html, README.md, this handoff file when changed, and required assets/source.

WEB -> GITHUB -> VERCEL SYNC
- main branch is the production source.
- Vercel deploys the root index.html automatically after a successful push to main.
- Always update TONU_WEB_BUILD in the HTML to the new version number.
- After pushing, fetch https://tonustudy.vercel.app/?verify=NNN with cache bypass and
  confirm BOTH the matching TONU_WEB_BUILD and a string unique to the new feature.
- A Git push is not proof of a live deployment; the live response check is required.

ANDROID APK SYNC MODEL
- Android wrapper source is app\.
- The wrapper loads https://tonustudy.vercel.app/ in a WebView. Therefore ordinary
  HTML/CSS/JS changes reach the installed APK after the Vercel deployment without
  rebuilding the APK, subject to WebView/network cache refresh.
- Fully close/reopen the app after a web deployment if the old interface remains.
- Native code owns Android-only behavior: app back handling, Android account picker,
  file selection, launch screen, connectivity treatment, and external links.
- Only change app\ and rebuild/upload the APK when native behavior, app icon,
  splash, package/version, Google Sign-In, or WebView configuration changes.
- For an APK release, increment versionCode and versionName in app\build.gradle.kts,
  run the Android workflow, install the generated APK, and test it before replacing
  the GitHub release asset. Never label an APK working without an install test.
- Release workflow: .github\workflows\android.yml
- Release tag: android
- Android download URL:
  https://github.com/tanmysarker733-svg/tonustudyv2/releases/download/android/Tonu.Study.apk

DATA AND AUTH BOUNDARIES
- Browser localStorage and Android WebView localStorage are separate.
- Cross-device study-data sync is only real when Firebase Auth plus Firestore save
  and restore are configured and verified for the same signed-in user.
- Do not claim cloud sync, Google sign-in, username/password, or APK native sign-in
  works based solely on visible UI. Test successful sign-in and a write/read round trip.
- Passwords must never be stored, displayed, or written to Firestore by page code.
- Username/password linking uses a Firebase Auth alias for the current Firebase UID.
- Firebase configuration/rules are in firestore.rules, firebase.json, and .firebaserc.

SAFE EDITING PRACTICE
- This is a large single-file application. Prefer targeted replacements around stable
  IDs/classes; do not reformat the entire HTML or rewrite unrelated markup.
- Preserve existing working functions. Add new behavior through isolated helpers and
  delegated data-action click handling where the application already uses it.
- Use UTF-8 without BOM. Windows/PowerShell writes can corrupt emoji/Bengali encoding;
  inspect visible strings after modifications.
- Use apply_patch for edits. Do not use destructive git reset/checkout.
- build-artifacts\ is user-owned and often untracked; do not stage, delete, or modify
  it unless the user directly requests an artifact operation.

MINIMUM VALIDATION FOR EVERY WEB CHANGE
1. Confirm the n+1 file exists and the older version is unchanged.
2. Extract every <script> block and run node --check on each extracted script.
3. Run git diff --check.
4. Check expected feature strings/data-actions exist and stale strings are absent.
5. Hash-compare the numbered file, repository index.html, and Version 2 mirror.
6. Inspect desktop + narrow mobile layout and dark + light mode where affected.
7. Test the interaction itself: click, close/back, scroll, and a second invocation.
8. Commit only intended tracked files. Keep unrelated/untracked user files out.
9. Push main, verify remote commit hash, then verify live Vercel content.
